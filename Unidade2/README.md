## 1. Cenário / Problema

A atividade apresenta uma startup de tecnologia em crescimento que enfrenta dificuldades na organização e no gerenciamento de seus projetos.

Entre os principais problemas identificados estão as falhas de comunicação entre as equipes, os atrasos nas entregas, o retrabalho durante o desenvolvimento e a ausência de relatórios para acompanhar o andamento dos projetos.

A empresa necessita de uma solução que permita organizar as atividades, melhorar a comunicação entre os colaboradores e acompanhar o desempenho dos projetos de maneira mais eficiente.

## 2. Stakeholders Envolvidos

Os principais stakeholders envolvidos no projeto são:

| Stakeholder | Interesse no projeto |
|---|---|
| Gestores e gerentes de projetos | Acompanhar o andamento dos projetos, controlar prazos e avaliar resultados. |
| Desenvolvedores | Organizar tarefas, acompanhar atividades e colaborar com os demais integrantes da equipe. |
| Líderes de equipe | Distribuir atividades, acompanhar o desempenho e organizar as entregas. |
| Clientes | Acompanhar o desenvolvimento dos projetos e receber entregas de acordo com suas necessidades. |
| Equipe de suporte / TI | Garantir o funcionamento, a manutenção e a integração do sistema. |
| Diretoria | Acompanhar os resultados gerais e tomar decisões estratégicas. |

## 3. Requisitos de Negócio

Os requisitos de negócio representam os objetivos estratégicos que a startup deseja alcançar com a implantação da solução.

- Melhorar a comunicação entre as equipes envolvidas nos projetos.
- Reduzir os atrasos nas entregas.
- Diminuir o retrabalho durante o desenvolvimento.
- Melhorar a organização e o acompanhamento das atividades.
- Aumentar a produtividade das equipes.
- Permitir que os gestores acompanhem o desempenho dos projetos por meio de relatórios.
- Melhorar o controle dos prazos e das entregas.

## 4. Requisitos das Partes Interessadas

Os requisitos das partes interessadas representam as necessidades específicas de cada grupo envolvido no projeto.

| Stakeholder | Necessidades |
|---|---|
| Gestores e gerentes de projetos | Visualizar o andamento dos projetos, acompanhar prazos e obter relatórios de desempenho. |
| Desenvolvedores | Consultar tarefas, atualizar o andamento das atividades e colaborar com a equipe. |
| Líderes de equipe | Distribuir tarefas, acompanhar a produtividade e identificar atividades atrasadas. |
| Clientes | Acompanhar o progresso dos projetos e verificar o cumprimento das entregas. |
| Equipe de suporte / TI | Garantir a integração com outras ferramentas e realizar a manutenção do sistema. |
| Diretoria | Consultar indicadores gerais e obter informações para a tomada de decisões. |

## 5. Requisitos da Solução

### 5.1. Requisitos Funcionais

Os requisitos funcionais descrevem as funcionalidades que o sistema deverá oferecer.

1. O sistema deve permitir criar e gerenciar projetos.
2. O sistema deve permitir cadastrar, editar, atribuir e acompanhar tarefas.
3. O sistema deve permitir organizar as atividades em um backlog.
4. O sistema deve permitir planejar e acompanhar sprints.
5. O sistema deve permitir que os desenvolvedores atualizem o andamento das tarefas.
6. O sistema deve permitir que os gestores acompanhem o progresso dos projetos.
7. O sistema deve gerar relatórios automáticos sobre o desempenho dos projetos.
8. O sistema deve permitir a integração com ferramentas de desenvolvimento e comunicação, como GitHub, Slack e Trello.

### 5.2. Requisitos Não Funcionais

Os requisitos não funcionais descrevem as características e condições de funcionamento do sistema.

1. O sistema deve possuir uma interface simples e intuitiva.
2. O sistema deve apresentar bom desempenho durante o acesso e a atualização das informações.
3. O sistema deve garantir a segurança das informações dos projetos.
4. O sistema deve permitir acesso simultâneo de diferentes usuários.
5. O sistema deve apresentar disponibilidade adequada para o funcionamento das equipes.
6. O sistema deve permitir integração com ferramentas externas utilizadas pela startup.

### 5.3. Requisitos de Transição

Os requisitos de transição representam as necessidades temporárias para permitir a implantação e a utilização da nova solução.

1. Migrar as informações dos projetos que atualmente estão armazenadas em planilhas ou outras ferramentas.
2. Realizar o cadastro dos usuários e definir seus respectivos níveis de acesso.
3. Configurar as integrações com as ferramentas utilizadas pela empresa.
4. Capacitar os colaboradores para utilizar o novo sistema.
5. Realizar testes antes da implantação definitiva da solução.

## 6. Priorização

Os requisitos foram classificados conforme sua importância para o funcionamento da solução e para o atendimento das necessidades da startup.

| Prioridade | Requisitos |
|---|---|
| **Essenciais** | Criar e gerenciar projetos; cadastrar e acompanhar tarefas; organizar backlog; acompanhar o andamento dos projetos; controlar prazos e atividades. |
| **Importantes** | Planejar e acompanhar sprints; gerar relatórios de desempenho; permitir diferentes níveis de acesso; migrar os dados existentes. |
| **Desejáveis** | Integração com GitHub, Slack e Trello; personalização dos relatórios; funcionalidades adicionais de acompanhamento e comunicação. |

## 7. Solução Proposta

A solução proposta consiste no desenvolvimento de um sistema web de gerenciamento ágil de projetos, centralizando as informações e atividades da startup em uma única plataforma.

O sistema permitirá criar projetos, organizar tarefas em backlog, planejar sprints e acompanhar o andamento das atividades. Também oferecerá relatórios para que os gestores possam visualizar o desempenho das equipes e identificar possíveis atrasos.

Além disso, a solução poderá contar com integrações com ferramentas como GitHub, Slack e Trello, facilitando a comunicação entre os colaboradores e o acompanhamento do desenvolvimento dos projetos.

## 8. Justificativa

A implantação de um sistema de gerenciamento ágil de projetos atende às necessidades da startup porque centraliza as informações, melhora a comunicação entre as equipes e facilita o acompanhamento das atividades.

A organização das tarefas em backlog e sprints permite um melhor planejamento do trabalho, contribuindo para a redução dos atrasos e do retrabalho.

Os relatórios de desempenho oferecem aos gestores informações importantes para acompanhar os resultados e tomar decisões. Já as integrações com ferramentas externas facilitam a colaboração entre os desenvolvedores e demais integrantes da equipe.

Dessa forma, a solução contribui para melhorar a organização, aumentar a produtividade e tornar o gerenciamento dos projetos mais eficiente.
